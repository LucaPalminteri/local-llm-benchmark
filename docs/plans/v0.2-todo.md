# v0.2 - Ordered Execution Checklist

This is the chronological implementation checklist for
[v0.2 Interactive Performance](v0.2-interactive-performance.md). Complete the
phases in order unless a task explicitly says it can happen in parallel.

Effort estimates are rough focused-development time. Real-model validation can
take longer because it includes model loading and repeated benchmark runs.

- Previous release: `v0.1.0`
- Active release: `v0.2`
- Current phase: Phase 2 - define interactive configuration and workload contracts
- Completed v0.2 phases: 1 of 10

## Phase 3 - Implement server lifecycle management

Estimated effort: two to three days

Dependency: Phase 2

### Command and startup

- [ ] Add a dedicated server lifecycle module.
- [ ] Build the `llama-server` argument array without shell interpolation.
- [ ] Record the exact command, process ID, process-start timestamp, and log
  paths.
- [ ] Detect an occupied configured port before starting.
- [ ] Safely allocate a port when automatic allocation is configured.
- [ ] Start the server with stdout and stderr capture.

### Readiness

- [ ] Poll the health endpoint until the model is ready.
- [ ] Use a monotonic high-resolution clock for elapsed startup timing.
- [ ] Distinguish process startup from model-ready time.
- [ ] Detect process exit before readiness.
- [ ] Apply a configurable readiness timeout.
- [ ] Store a structured failure kind and message for failed startup.
- [ ] Preserve server logs after every failure.

### Cleanup

- [ ] Stop the server after successful runs.
- [ ] Stop the complete process tree after failures, timeouts, and user
  interruption.
- [ ] Make cleanup safe when the server already exited.
- [ ] Verify that the selected cleanup strategy works on Windows.
- [ ] Avoid leaving a port occupied after cleanup.

### CLI

- [ ] Add `llmbench server check --config ...`.
- [ ] Make the command start the configured server, wait for readiness, report
  startup timing, and cleanly stop it.

### Tests

- [ ] Test command construction.
- [ ] Test successful readiness polling.
- [ ] Test occupied-port behavior.
- [ ] Test readiness timeout.
- [ ] Test early process exit.
- [ ] Test preservation of failed-start logs.
- [ ] Test normal and exceptional process-tree cleanup.

### Exit check

- [ ] `llmbench server check` reliably starts and stops the real local server.
- [ ] No `llama-server` child process remains after success, failure, timeout,
  or interruption.

## Phase 5 - Implement the streaming request client

Estimated effort: two to three days

Dependency: Phase 4

### HTTP and stream handling

- [ ] Select and add the streaming HTTP dependency.
- [ ] Send OpenAI-compatible streaming chat-completion requests.
- [ ] Parse server-sent events across arbitrary network chunk boundaries.
- [ ] Recognize the normal end-of-stream marker.
- [ ] Retain raw response events for debugging.
- [ ] Preserve response status, headers needed for diagnosis, and request
  identifiers when available.

### Client timing

- [ ] Use a monotonic high-resolution clock.
- [ ] Record request start.
- [ ] Record the first non-empty streamed content token.
- [ ] Record the final content token.
- [ ] Record stream completion.
- [ ] Calculate TTFT from request start to first content token.
- [ ] Do not treat HTTP headers, comments, role-only deltas, or empty content
  as the first token.
- [ ] Calculate total response time independently of server timing.

### Usage and failures

- [ ] Store server-reported timing fields when available.
- [ ] Store server-reported prompt, completion, and total token counts.
- [ ] Keep client and server timing in separate fields.
- [ ] Detect malformed events.
- [ ] Detect premature stream termination.
- [ ] Detect request timeout and connection failure.
- [ ] Detect output truncation, including the server's finish reason.
- [ ] Store structured failures instead of dropping failed attempts.

### Tests

- [ ] Test events split across arbitrary chunks.
- [ ] Test multiple events arriving in one chunk.
- [ ] Test role-only and empty deltas before the first content token.
- [ ] Test normal stream completion.
- [ ] Test malformed JSON and malformed event framing.
- [ ] Test premature EOF, timeout, connection failure, and truncation.
- [ ] Test client/server timing separation.

### Exit check

- [ ] One real request produces inspectable raw events and a normalized result.
- [ ] TTFT is demonstrably measured at first streamed content.

## Phase 6 - Build the interactive runner and artifact workflow

Estimated effort: two to three days

Dependency: Phase 5

### Run sequence

- [ ] Create the run and fully resolved manifest before starting the server.
- [ ] Start the server and record model-ready timing.
- [ ] Resolve workload token counts after the server is ready.
- [ ] Execute and label warm-up requests.
- [ ] Execute exactly one first/cold measured request where configured.
- [ ] Execute warm uncached requests.
- [ ] Execute warm cached-prefix requests.
- [ ] Stop the server in a guaranteed cleanup path.
- [ ] Preserve partial results after interruption.

### Artifact layout

- [ ] Store the resolved manifest and environment information.
- [ ] Store server command, PID, startup events, and readiness timing.
- [ ] Store combined and per-request server logs where useful.
- [ ] Store one normalized request result per JSONL line.
- [ ] Store raw request and response events per attempt.
- [ ] Store structured startup, request, timeout, truncation, and cleanup
  failures.
- [ ] Keep raw artifacts immutable.
- [ ] Make summaries and reports regenerable from stored samples.

### Safety and resumption

- [ ] Decide and document whether interactive runs can be resumed safely.
- [ ] If supported, verify manifest, workload, protocol, and phase compatibility
  before resuming.
- [ ] If deferred, reject resume requests clearly and preserve interrupted
  artifacts.

### CLI

- [ ] Add `llmbench interactive run --config ...`.
- [ ] Report the run ID, status, artifacts path, and concise result summary.
- [ ] Handle Ctrl+C without losing completed attempts or leaving the server
  running.

### Tests

- [ ] Test the complete phase execution order.
- [ ] Test that warm-up samples are marked.
- [ ] Test partial-result preservation.
- [ ] Test cleanup on request failure and interruption.
- [ ] Test sample and raw-event artifact paths.

### Exit check

- [ ] The interactive smoke configuration completes end to end.
- [ ] Every attempted request is represented by a success or failure result.
- [ ] Server cleanup occurs for every terminal run path.

## Phase 7 - Add interactive statistics and reports

Estimated effort: one to two days

Dependency: Phase 6

### Aggregation rules

- [ ] Exclude warm-up requests from normal summary statistics.
- [ ] Group by model, runtime, workload, and measurement phase.
- [ ] Never combine cold, warm uncached, and warm cached samples.
- [ ] Define and document the percentile calculation method.
- [ ] Calculate median and p95 TTFT.
- [ ] Calculate median total response time.
- [ ] Calculate median prompt-processing tokens per second.
- [ ] Calculate median generation tokens per second.
- [ ] Calculate median completion-token count.
- [ ] Calculate cache-reuse tokens or ratio.
- [ ] Calculate error and truncation rates using all measured attempts.
- [ ] Represent missing measurements as `null`, never as a fabricated zero.

### Report formats

- [ ] Add a concise terminal report.
- [ ] Add a Markdown report.
- [ ] Add a CSV report.
- [ ] Show startup/model-ready duration separately from request latency.
- [ ] Show client-observed and server-reported timing separately.
- [ ] Surface partial, failed, and truncated runs clearly.

### CLI

- [ ] Add `llmbench interactive report <run-id>`.
- [ ] Add `llmbench interactive report --latest`.
- [ ] Prevent a raw report command from silently reading an interactive run and
  vice versa.

### Tests

- [ ] Test median and p95 with odd, even, and small sample sets.
- [ ] Test warm-up exclusion.
- [ ] Test measurement-phase separation.
- [ ] Test error and truncation rates.
- [ ] Test missing timing and usage values.
- [ ] Test deterministic regeneration from stored artifacts.

### Exit check

- [ ] Deleting generated summaries and reports and regenerating them produces
  the same results from stored samples.
- [ ] The report directly answers startup time and small/medium/large

## Explicitly deferred beyond v0.2

Do not add these while completing this checklist:

- Concurrent-user throughput testing
- RAM, VRAM, or system telemetry
- Task correctness or quality scoring
- Repository agents
- A large prompt library
- Dashboard UI
- A combined model score
