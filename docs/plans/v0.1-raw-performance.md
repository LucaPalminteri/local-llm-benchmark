# v0.1 - Raw Performance MVP

## Goal

Create the Python project, command-line interface, configuration format, and
artifact layout required to run reproducible raw inference benchmarks through
`llama-bench`.

At the end of this version, two local GGUF configurations should be comparable
without manually editing PowerShell commands or spreadsheets.

## User workflow

```powershell
llmbench doctor
llmbench plan --config configs/experiments/raw-smoke.yaml
llmbench raw run --config configs/experiments/raw-smoke.yaml
llmbench raw report --latest
llmbench compare <run-id-a> <run-id-b>
```

## Scope

### Project foundation

- Create an installable Python package and CLI entry point.
- Add formatting, linting, type checking, and automated tests.
- Define application and result schema versions.
- Add clear Windows development and installation instructions.

### Configuration

Define validated configuration models for:

- Model identity and GGUF path
- `llama-bench.exe` path
- Expected `llama.cpp` build or commit
- GPU layers
- Flash attention
- KV-cache key and value types
- Context depth
- Prompt and generation token counts
- Repetitions
- Threads, batch size, and micro-batch size
- Timeout and output directory

Configuration should be split into reusable model, runtime-profile, and
experiment definitions. The runner must write one fully resolved manifest for
every run.

### CLI behavior

Implement:

- `doctor`: validate binaries, model files, output paths, and basic device
  discovery.
- `plan`: expand the benchmark matrix and show the number of cases without
  executing them.
- `raw run`: execute the planned `llama-bench` cases.
- `raw report`: summarize one run.
- `compare`: compare compatible raw-performance runs.

### Execution

- Invoke `llama-bench` without shell-string interpolation.
- Request a machine-readable output format.
- Capture standard output, standard error, exit code, start time, and end time.
- Apply a per-process timeout.
- Preserve partial output when a case fails.
- Support interruption without overwriting completed data.
- Record the exact argument array used for each process.

### Storage

Create one directory per run:

```text
runs/<run-id>/
|-- manifest.json
|-- environment.json
|-- events.jsonl
|-- samples.jsonl
|-- summary.json
|-- raw/
|   `-- llama-bench.json
`-- logs/
    |-- stdout.log
    `-- stderr.log
```

Normalize individual repetitions into one sample per JSONL line. Preserve the
original `llama-bench` output separately.

### Statistics and reporting

Calculate, where applicable:

- Sample count
- Median
- Arithmetic mean
- Standard deviation
- Minimum and maximum
- Failed-sample count

Reports should distinguish:

- Prompt processing
- Text generation
- Prompt-plus-generation
- Context depth
- KV-cache configuration

Produce terminal, CSV, and Markdown output.

## Out of scope

- Starting `llama-server`
- TTFT and streaming measurements
- RAM or VRAM sampling
- Quality tasks
- Repository agents
- SQLite
- Web dashboards

## Acceptance criteria

- A fresh installation can run `llmbench doctor`.
- A dry run shows the fully expanded benchmark matrix.
- One command benchmarks at least two context depths and two generation sizes.
- Seven repetitions are stored as individually inspectable samples.
- A terminated or failing case appears in the result set with a failure reason.
- Re-running report generation produces the same summary from raw artifacts.
- Two model or runtime configurations can be compared in a Markdown table.
- Unit tests cover configuration validation, command construction, result
  parsing, and statistical aggregation.

## First smoke experiment

Keep the first successful experiment deliberately small:

```yaml
prompt_tokens: [512]
generation_tokens: [128]
context_depths: [0, 2048]
repetitions: 2
```

After the complete pipeline works, increase to the real seven-repetition
matrix. This separates runner bugs from long or memory-intensive experiments.

## Definition of done

`v0.1` is complete when raw benchmark results can be generated, interrupted,
inspected, summarized, and compared without manual transformation.
