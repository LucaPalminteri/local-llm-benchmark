# v0.5 - Agentic Coding

## Goal

Measure whether a model can complete realistic React, Next.js, TypeScript, and
Node.js work inside a repository when every model receives the same agent,
tools, permissions, budgets, and starting commit.

This is the most important quality milestone for the intended use case.

## User workflow

```powershell
llmbench agent doctor
llmbench repo-task validate tasks/repository/
llmbench agent run --suite configs/suites/repository-smoke.yaml
llmbench agent inspect <attempt-id>
llmbench agent report <run-id>
```

## Scope

### Fixed agent adapter

Integrate one fixed coding agent or implement one deliberately minimal agent
loop. Record:

- Agent name and version
- System prompt
- Tool schemas
- Chat template
- Context limit
- Maximum turns
- Maximum generated tokens
- Wall-clock timeout
- Command permissions
- Context-compaction behavior

Every model in a comparison must use the same compatible agent profile.

### Initial tools

Keep the first tool set small:

- List files
- Read file
- Search text
- Apply patch
- Run an allowed command

Tool requests, results, durations, failures, and output truncation must be
stored as an event transcript.

### Repository isolation

For every attempt:

1. Resolve an exact starter commit.
2. Create a clean disposable working copy.
3. Expose task instructions and allowed public tests.
4. Keep hidden graders outside the model-visible repository.
5. Run the agent.
6. Capture the final diff and repository status.
7. Apply policy checks.
8. Execute hidden grading.
9. Archive artifacts and safely dispose of the working copy.

### Initial repository suite

Create five small tasks:

- One React task
- Two Next.js tasks
- One Node.js task
- One TypeScript or debugging task

Tasks should represent work that would normally take approximately 20 to 60
minutes manually.

### Scoring

Implement the proposed 100-point structure:

| Check | Points |
|---|---:|
| Hidden functional tests | 50 |
| Typecheck and production build | 15 |
| Browser tests | 15 |
| Explicit requirements | 10 |
| No forbidden test or configuration changes | 5 |
| Patch quality | 5 |

Functional tests and production build remain mandatory for a full pass.

### Policy checks

Detect and reject or penalize:

- Modified hidden or protected tests
- Disabled TypeScript checking
- Broad lint suppression
- Changed package scripts that skip validation
- Deleted tests
- Hardcoded visible examples
- Files written outside allowed paths

### Metrics

Report:

- Agentic Pass@1
- Mean score
- Consistency
- Tasks completed per hour
- Total and generated tokens
- Tool calls and iterations
- Time spent generating, using tools, and grading
- Failure category

## Out of scope

- Multiple competing agent implementations
- Unrestricted shell access
- Network-dependent tasks
- A 30-task suite
- Human preference evaluation as the main grader

## Acceptance criteria

- Every attempt begins from the same verified commit.
- Five repository tasks run end to end.
- Hidden tests are never present in the agent-visible working copy.
- The final patch, transcript, tests, timing, and score are retained.
- Forbidden modifications are detected automatically.
- Agent and model failures are categorized separately.
- A stopped or crashed attempt does not contaminate the next attempt.
- Automated tests cover workspace preparation, policy checks, grading,
  transcript storage, and cleanup target validation.

## Definition of done

`v0.5` is complete when at least two models can be compared on five clean,
repeatable repository tasks using the same agent and budgets.
