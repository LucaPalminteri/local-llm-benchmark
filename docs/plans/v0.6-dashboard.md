# v0.6 - Results Dashboard

## Goal

Provide a visual interface for exploring benchmark history without moving
execution or canonical scoring logic out of the Python benchmark core.

The dashboard is a consumer of stored results, not the source of truth.

## Architecture

```text
Python runner
    |
    +-- immutable run artifacts
    |
    `-- SQLite result catalog
             |
             v
      read-only results API
             |
             v
       Next.js dashboard
```

The exact web stack can be revisited at implementation time. A Next.js
dashboard is a natural fit for the project's web-development focus, while a
small Python API can expose normalized results and artifact metadata.

## Scope

### Result catalog

- Add a SQLite catalog for indexed metadata and normalized measurements.
- Keep large logs, responses, patches, and raw time series in artifact files.
- Import existing `v0.1` through `v0.5` runs.
- Rebuild the catalog from artifacts.
- Track schema and benchmark-protocol versions.

### Read-only API

Expose:

- Models and model artifacts
- Runtime profiles
- Runs and attempts
- Raw-performance measurements
- Interactive latency
- Resource summaries
- Quality scores
- Repository-task results
- Links or identifiers for underlying artifacts

The API must not silently compare incompatible benchmark protocols.

### Dashboard views

Implement:

1. **Overview**
   - Latest models and configurations
   - Key metrics without a combined opaque score

2. **Raw performance**
   - Prompt speed by prompt size
   - Generation speed by context depth
   - Quantization and KV-cache comparison

3. **Interactive performance**
   - TTFT distribution
   - Total response time
   - Cold versus warm behavior

4. **Resources**
   - Peak RAM and VRAM
   - Resource usage over time for an individual run

5. **Quality**
   - Reasoning and one-shot coding Pass@1
   - Category breakdown
   - Consistency and token efficiency

6. **Agentic coding**
   - Repository-task Pass@1
   - Tasks per hour
   - Failure categories
   - Attempt drill-down with patch, transcript, and grader results

7. **Run comparison**
   - Select compatible configurations
   - Highlight improvements and regressions

### Export

- Export visible comparisons to CSV.
- Generate a shareable static Markdown or HTML summary.
- Include configuration and protocol identifiers in exports.

## Out of scope

- Executing benchmarks from the browser
- Editing benchmark tasks
- Remote multi-user authentication
- Cloud result synchronization
- A single overall leaderboard score

## Acceptance criteria

- The catalog can be deleted and rebuilt from raw artifacts.
- Old compatible runs appear without being rerun.
- Dashboard filters include model, quantization, KV cache, context, engine
  build, experiment, and date.
- Charts show sample counts and failure counts.
- Incompatible runs are marked rather than merged.
- Every aggregate can be traced to its run and raw artifacts.
- The UI works with partially populated tracks.
- API and dashboard tests cover the primary comparison and drill-down flows.

## Definition of done

`v0.6` is complete when a user can visually compare speed, latency, resources,
model-only quality, and agentic quality while retaining a path back to every
underlying result.
