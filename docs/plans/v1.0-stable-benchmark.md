# v1.0 - Stable Benchmark

## Goal

Release a documented, repeatable benchmark tool that answers which local model
and configuration is most useful for coding on the target Windows 11, AMD
Radeon RX 6700 XT, and Vulkan setup.

`v1.0` is primarily a stability, validity, and usability release. It should not
be a last-minute collection of unrelated features.

## Scope

### Stable benchmark protocol

- Version the raw, interactive, model-quality, and agentic protocols.
- Freeze comparison rules for the first stable suite.
- Document which changes invalidate direct comparisons.
- Provide deterministic and model-native sampling profiles.
- Define official timeout, token, and iteration budgets.

### Expanded private suite

Grow toward:

- A compact but representative general-reasoning suite
- Approximately 40 one-shot coding tasks
- Approximately 30 repository tasks

Expand only after measuring duplication, task discrimination, grader
reliability, and runtime cost. Task count alone is not a quality target.

### Reproducibility

- Provide example configurations for the target hardware.
- Capture application, task-suite, agent, and `llama.cpp` versions.
- Document model-file hashing and artifact identity.
- Support rerunning a resolved manifest.
- Provide backup and migration instructions for runs and the catalog.

### Reliability

- Verify process cleanup under interruption.
- Verify atomic writes and recovery from partial runs.
- Add end-to-end smoke tests.
- Test schema migrations with retained historical fixtures.
- Document expected telemetry accuracy and limitations.
- Confirm that report regeneration is deterministic.

### Documentation

Publish:

- Installation guide
- First benchmark tutorial
- Configuration reference
- Task-authoring guide
- Grader-authoring guide
- Agent-profile reference
- Result interpretation guide
- Troubleshooting guide
- Benchmark methodology and limitations

### Stable reporting

Keep these dimensions visible:

- Agentic coding Pass@1
- Model-only coding Pass@1
- Successfully completed repository tasks per hour
- General-reasoning accuracy
- Warm TTFT
- Generation speed at 8K context
- Peak VRAM and RAM

Do not introduce a mandatory combined score. Optional user-defined ranking
preferences may order models, but underlying dimensions must remain visible.

## Release criteria

- A new user can install the tool and complete the tutorial on Windows.
- At least two model configurations can run through every stable track.
- Run manifests reproduce the same benchmark procedure.
- All primary metrics can be regenerated from retained artifacts.
- The dashboard and CLI agree on aggregates.
- The stable suite has documented licenses or provenance for distributable
  tasks.
- Hidden private tasks and graders cannot be exposed through normal reports.
- Known limitations and measurement uncertainty are documented.
- No critical data-loss, unsafe-cleanup, or hidden-test exposure issues remain.

## Post-v1 possibilities

Potential later work includes:

- Additional inference engines
- Multiple hardware profiles
- Concurrent throughput experiments
- Energy-efficiency measurement
- Optional public benchmark adapters
- Remote workers
- Comparison of coding-agent implementations

These should remain separate from the stable local single-machine benchmark
until their experimental variables and fairness rules are clearly defined.

## Definition of done

`v1.0` is complete when the benchmark can be used repeatedly to make a
defensible local-model choice, and another person can understand how every
reported result was produced.
